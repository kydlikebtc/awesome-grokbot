# Refreshing the screenshots

`docs/screenshots/*.png` show live counts, so they go stale as the catalog
grows. On 2026-09-22 they still read 361 while the catalog held 1894 — off by
5.2x, which made the repo look both small and abandoned.

They are **not** regenerated by the daily job. Rendering them needs a browser,
and committing a fresh ~350 KB PNG every day would add ~120 MB of history a
year to show a number the README already states in text. Refresh them by hand
when the count has moved enough to look wrong — in practice every few weeks.

## Steps

```bash
cp catalog.json site/catalog.json          # the site reads its own copy
python3 -m http.server 8750                # from the repo root
```

Then, in a browser driven at the exact viewport (the sizes matter — the social
card is cropped to 2:1 by X, Slack and GitHub):

| File | URL | Viewport | Notes |
| --- | --- | --- | --- |
| `site-desktop.png` | `/site/index.html` | 1400x1180 | scrolled to top |
| `site-chinese.png` | `/site/index.html#q=email&lang=zh` | 1400x760 | scrolled past the header |
| `social-card.png` | `/docs/social-card.html` | **1280x640** | must stay exactly 2:1 |

Before each shot, disable the row animation so nothing is captured mid-fade:

```js
document.documentElement.style.scrollBehavior = 'auto';
document.querySelectorAll('li.row').forEach(r => r.style.animation = 'none');
```

## After

- `site-desktop.png` and `site-chinese.png` are referenced by the READMEs and
  need no further action.
- `social-card.png` must be **uploaded by hand** at Settings → General → Social
  preview. GitHub exposes no API for it, so a commit alone does not change what
  X or Slack shows when someone pastes the repo link.
